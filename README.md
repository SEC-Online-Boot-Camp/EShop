# rehearsal ブランチ（講師専用）

AI活用入門講座 SW編の**事前リハーサル**で使うものを置いてある。**受講者はこのブランチに切り替えない。** 講座当日に受講者のPCで詰まったときは、`precheck.ps1`だけを取り出して診断に使う（[講座当日の診断](#講座当日の診断受講者のpc)）。

`main`・`coupon`とは履歴を共有しない独立したブランチで、**アプリのコードは入っていない**。受講者が`git clone`したときに、このブランチの内容が作業ツリーへ展開されないようにするためである。

> **このブランチは公開リポジトリにあり、受講者からも参照できる。** 普通の`git clone`はすべてのブランチをリモート追跡ブランチとして取得するため、`git show origin/rehearsal:precheck.ps1`で中身を読める。**受講者に伏せたい情報（演習の答え・仕込んだ欠陥の件数など）はここに書かない。** 期待するテスト件数（54件・55件）は配布する手順書（03-01〜03-03）に既に書かれているので差し支えない。

## 中身

| ファイル                              | 用途                                                                       |
| :------------------------------------ | :------------------------------------------------------------------------- |
| `precheck.ps1`                        | 事前確認書 第I部（実機確認）を1ステップずつ進める対話型ランナー。`-Diagnose`で講座当日の診断にも使う |
| `docs-template/要件整理メモ.md`       | リハーサル用のダミー成果物。本来はNo.2で受講者が作るもの                   |
| `docs-template/API設計書.md`          | 同上                                                                       |

`docs-template`の2ファイルは、`precheck.ps1`の4-4-01でリハーサル機の`EShop/docs/`へコピーされる。No.3の手順書（03-01〜03-03）がNo.2の成果物を参照する前提で書かれているため、リハーサルではこれで代用する。**解答例は講師専用資料なので、このPublicリポジトリには置かない。**

## 使い方

リハーサル機で次を実行する。受講者が使う`main`・`coupon`は取得されない。

```powershell
$base = "C:\rehearsal-$(Get-Date -Format 'yyyyMMdd')"
New-Item -ItemType Directory -Force $base | Out-Null
Set-Location $base
git clone -b rehearsal --single-branch https://github.com/SEC-Online-Boot-Camp/EShop.git EShop-rehearsal
Set-Location EShop-rehearsal
.\precheck.ps1 -DryRun            # 下見（何も実行しない）
.\precheck.ps1                    # 実環境リハーサル
```

止まるのは人が操作・判断するところだけで、機械が判定できるステップは確認を求めずに流す。**自動で流したステップの判定がNGになったときは、その場で止まる。**

| 呼び方 | 用途 | 項目数 | 止まる箇所 |
| :-- | :-- | --: | --: |
| `.\precheck.ps1` | 実環境リハーサル（貸与機） | 46 | 17 |
| `.\precheck.ps1 -Chapter 5` | 社内で確定させる5章の挙動確認 | 11 | 10 |
| `.\precheck.ps1 -Auto` | 講師の下ごしらえ・再実行 | 46 | 0 |

**5章（5-1〜5-11）は`-Chapter 5`と書いたときだけ対象になる。** 社内で先に潰しておく前提で、貸与機では測れないため既定から外してある。

**VS Codeの統合ターミナルから起動する。** 2-2-dで記録するのは起動したシェルの版で、受講者は01-01の最初から最後までVS Codeのターミナルで操作する。素のPowerShellから起動すると3章の結果が受講者の環境を表さない。

`.ps1`の実行が実行ポリシーで禁止されている場合の起動方法は`precheck.ps1`の冒頭に書いてある。

## 置き場所

**作業フォルダ（EShopのclone先）と記録の出力先は、既定で「このリポジトリを置いたフォルダの親」になる。** 置き場にしたいフォルダを作ってその中へcloneすれば、**リハーサルが終わったらフォルダごと1回で片付く**。`-WorkDir`・`-OutDir`に同じ値を渡す必要はない。

```text
C:\work\                  ← 置き場（手で作る。名前は何でもよい）
├── EShop-rehearsal\      ← このリポジトリのクローン
├── EShop\                ← 4-3-05 でcloneする作業ツリー
├── precheck-result-<日時>.md
├── precheck-steps-<日時>.md
└── rehearsal-check.txt
```

- **`EShop`の中には置かない。** 入れ子のリポジトリになり、7-1の`git status`の判定がぶれる
- 次のどれかに当たる場合は`C:\rehearsal-<日付>`を作ってそこを使う（作れない機材では`%USERPROFILE%\rehearsal-<日付>`）。置き場が意図しない場所に決まるのを防ぐため
  - 正本を直接実行している（版印が`dev（未配備…）`）
  - ドライブ直下にcloneした（親が`C:\`になる）
  - 親がOneDrive配下。`.venv`と`.git`が同期対象になると**6章の所要時間の実測が当てにならなくなり**、記録の方も機材から消してクラウド側に残る
  - 実行ポリシー対策の起動で、カレントがこのリポジトリの置き場ではない
- **前日に用意しておいても置き場は割れない。** このスクリプトを`rehearsal-<日付>`の中に直に置いた場合は、実行日ではなくそのフォルダを使う
- `-WorkDir`・`-OutDir`で明示することもできる（OneDrive配下を指した場合は起動時に警告が出る）

## 講座当日の診断（受講者のPC）

受講者の環境で詰まったときに、**受講者自身に実行してもらい、講師は画面共有で結果を見る**。**読み取りだけ**で、clone・pip・seed・DBの削除・ブランチの切り替え・サーバーの起動は行わない。NG・注意の項目には手順書のどの手順をやり直すかが出るので、直す操作は受講者が手順書どおりに行う。

EShopを開いたVS Codeのターミナルで、次の4行を実行してもらう（`backend`にいてもよい）。チャットに貼って渡す。

```powershell
git fetch origin rehearsal
git -C (git rev-parse --show-toplevel) archive -o "$env:TEMP\eshop-diagnose.zip" origin/rehearsal precheck.ps1
Expand-Archive "$env:TEMP\eshop-diagnose.zip" "$env:TEMP\eshop-diagnose" -Force
& "$env:TEMP\eshop-diagnose\precheck.ps1" -Diagnose
```

4行目が「このシステムではスクリプトの実行が無効になっている」で弾かれたら、代わりに次を実行してもらう（起動方法3と同じ形）。

```powershell
& ([scriptblock]::Create((Get-Content "$env:TEMP\eshop-diagnose\precheck.ps1" -Raw))) -Diagnose
```

- **取り出しに`git archive`を使うのは、文字コードを変えないため。** `git show … > ファイル`はPowerShell 5.1で文字コードが変わり、スクリプトが壊れる。zipから展開したファイルにはインターネット由来の印も付かない
- **`EShop`の中には置かない。** `git status`に出て、受講者の成果物と混ざる
- 1〜3行目は2回目以降は要らない。rehearsalブランチを配備し直した日だけ、1行目から実行する

| 区分 | 見ること | NG・注意のときに示す手順 |
| :-- | :-- | :-- |
| 道具 | Python 3.11以上・Git・Claude Code（User PATHへの登録）・VS Code拡張・実行ポリシー | 01-01 前提条件・手順2、01-02 手順2・3 |
| リポジトリ | clone元・OneDrive配下か・ブランチ・配布された状態からの差分・`docs`・`.env`の`DATABASE_URL`（**値は表示しない**） | 01-01 手順1、03-01 手順0、01-04 手順3 |
| Python環境 | `backend\.venv`・そのターミナルで有効になっているか・`requirements.txt`との版の一致 | 01-01 手順2 |
| データベース | `ecommerce.db`の件数と、`coupon`で列が増えているか（**読み取り専用で開く**） | 01-01 手順3、03-01 手順0-2 |
| サーバー | 8000番を使っているアプリと、`/docs`・`/products`の応答（**起動はしない**） | 01-01 手順4 |
| テスト | 配布されたテストだけをpytest（`main` 54件・`coupon` 55件）。**自分で作ったテストは実行しない**（演習の途中では失敗してよいため） | 01-01 手順5、03-01 手順0-2 |
| Claude Codeの設定 | `CLAUDE.md`・`settings.json`のJSON・hookを試しに呼んで既存テストが止まるか | 01-03 手順2、03-02 手順2 |

- **ブランチで期待値が変わる。** `main`はNo.1・No.2、`coupon`はNo.3以降として判定する。No.3で「pytestは55件PASSするのに注文確定で落ちる」（DBの作り直し漏れ）も、DBの列から見分ける
- **hookは、Claude Codeと同じ入力でGit Bashから1回呼ぶ。** 既存の`tests\test_orders.py`へのEditで終了コード2、新しいファイルへのWriteで0になれば守れている。ツール自体は実行しないので、ファイルは変わらない
- **書き込むのは記録ファイルだけ。** pytestにはキャッシュとバイトコードを書かせない。hookを試すときに`%TEMP%`へ一時ファイルを作り、すぐ消す

| 引数 | 用途 |
| :-- | :-- |
| `-Network` | 事前確認書 3章と同じ確認（プロキシ設定の方式と、講座で使う10ホストへの到達性）を足す。ログイン・`pip install`・`git fetch`が落ちるなど、**通信が疑わしいときだけ講師が指示する** |
| `-SkipTest` | pytestを実行しない（約10秒短くなる） |
| `-EShopDir <path>` | 診断するEShopを指定する。既定はカレントから上へたどって見つける（EShopの親フォルダで起動した場合は直下の`EShop`） |
| `-OutDir <path>` | 記録の出力先。既定はEShopの親フォルダ |

`-Network`を付けると外部の複数ホストへまとめて接続するため、**監視下の機材では一括の疎通確認として記録に残る**。既定で行わないのはこのためで、判定の文面も事前確認書の章番号を指す講師向けのものになる。

**記録（`eshop-diagnose-<日時>.md`）は、講師が求めたときだけ共有フォルダにアップロードしてもらう。** 判定一覧・直し方・各項目の出力が入る。`.env`の値は含まず、`-Network`のときのプロキシのアドレス等は伏せ字になる。ファイルのパス（利用者名を含む）は残る。

## 保守

`precheck.ps1`のステップ番号・期待値は、**教材リポジトリにある`事前確認書.md`（第I部）と対になっている**。どちらかを直したら、もう一方も合わせること。

- ステップ番号は同書の節番号と揃えてある（`3-2-1`・`4-3-05`・`7-2-b`など）
- 期待値の出どころ: 同書 4-3（`main` 54件）・4-4（`coupon` 55件）・5章

**`-Diagnose`の項目（`D1-1`〜`D7-3`）は事前確認書ではなく、受講者向けの手順書（01-01〜03-02）の手順番号を指している。** 手順書の手順番号や、期待する件数（54件・55件）・シードの件数を変えたら、`Set-CheckList`の文面も合わせる。`deploy-rehearsal.py`の整合検査は`New-Step`だけを見るので、こちらは検査されない。
