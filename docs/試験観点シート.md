# 試験観点シート（結合テスト）

EShopの結合テストの試験観点をまとめる。根拠は`docs/基本設計書.md`である。

| 版 | 内容 |
| --- | --- |
| 1.0 | 初版（認証・商品一覧・カート・注文確定・稼働確認の結合テスト） |
| 1.1 | クーポン機能の結合テストの観点を追記 |
| 1.2 | 区分を正常系・異常系にし、境界値と回帰は試験観点の末尾に書き添える |
| 1.3 | 期待結果が未決・暫定の観点のテストは、reasonが「未決：」「暫定：」で始まるskipにする |
| 1.4 | 未決・対象外の観点の区分の決め方と、これから実装する機能の暫定の観点の扱いを書き足す |

## 1. このシートの範囲

このシートが扱うのは**結合テスト**である。APIを外から呼び、基本設計書のとおりに動くかを確かめる。

| 試験 | 確かめること | 根拠 | テストの置き場所 | このシート |
| --- | --- | --- | --- | --- |
| 結合テスト | APIの入出力と業務ルール（外から見た振る舞い） | 基本設計書 | `tests/integration/` | 扱う |
| 単体テスト | 関数・モデルの作り（内側の振る舞い） | コード | `tests/unit/` | 扱わない |

単体テストは開発者が書いたもので、`pytest`を実行すると結合テストと一緒に流れる。結合テストだけを流すときは`pytest tests/integration`とする。

## 2. 列の書き方

| 列 | 書くこと |
| --- | --- |
| No. | 機能ごとの記号と連番（例：`CART-03`）。一度振った番号は変えない |
| 区分 | 正常系／異常系。期待する結果で決める（受け付けられて期待どおりに処理されるなら正常系、エラーで弾かれるなら異常系）。期待結果が未決の観点や、確認方法が対象外の観点も、想定する結果で決める（例：候補がどれもエラーなら異常系）。境界値の観点は試験観点の末尾に「（境界値：…）」、回帰の観点は「（回帰：…）」と書き添える |
| 試験観点 | 何を確かめるか |
| 前提条件 | 試験の前に用意するデータと操作。テストで使うフィクスチャ名を書いてよい |
| 期待ステータス | HTTPステータス |
| 期待結果 | 応答の項目と値。金額は具体的な数値で書く（「正しく計算される」とは書かない） |
| 確認方法 | 下の表のどれか |
| 対応テスト | この観点を確かめるテストの関数名。ファイルは各章の見出しの下に書く。まだ無ければ空欄 |

表の列の幅は、空白でそろえない。1行を足したときに、ほかの行まで差分に出ないようにするためである。表は`Ctrl+K V`のプレビューで見る。

**確認方法**は、上から順に選ぶ。下ほど「ほかに方法がないときだけ」使う。

| 確認方法 | 内容 | 例 |
| --- | --- | --- |
| 応答 | 呼んだAPIの、ステータスと応答の項目を見る | `POST /cart/items`の`subtotal` |
| 別のAPI | 状態の変化を、ほかのAPIで見る | 注文確定のあとの`GET /cart`が空 |
| DB | どのAPIからも見えない結果を、データベースで見る | 注文に記録された値（注文を取得するAPIは無い） |
| 対象外 | このテスト環境では確かめられない。理由を書く | 同時実行（テストのDBでは直列に処理される） |

> エラーの`detail`の文言は試験の対象にしない（基本設計書10章）。異常系はステータスで判定する。

## 3. 機能を追加するときの書き方

機能を追加したら、次のように書き足す。既存の行は消さない。

- 追加した機能は、新しい節（例：「## 9. （追加した機能の名前）」）にまとめ、No.に新しい記号を使う。見出しの下に、対応テストのファイルを書く
- 既存の行の期待結果が変わるときは、その行を直し、試験観点の末尾に「（回帰：直した理由）」と書き添える。区分は変えない。
- 期待結果が決められない観点は、消さずに期待結果を「未決」とし、何が決まっていないかを書く
- 期待結果が未決・暫定の観点のテストは、`@pytest.mark.skip`を付け、reasonを「未決：」または「暫定：」で始める。暫定のときは、仮に決めた値とその根拠を書く
- まだ実装していない機能のテスト（先にテストを書くとき）は、暫定の観点を`skip`にせず、暫定値で書く。実装が無いので失敗してよい。未決の観点だけを`skip`にする
- 変更履歴には、追加した機能ごとに版を1行だけ足す。同じ機能の観点を何回かに分けて足しても、版は増やさない
