# デバッグレポート（クーポン機能）

No.3で、結合テスト（`backend/tests/integration/test_coupon.py`）の失敗から直した不具合の記録。判断の根拠は、確定版の基本設計書（`docs/基本設計書.md`）である。

## 1：発行数の上限がnullのクーポンを、上限0として扱っていた

- エラー内容：CPN-14 `test_apply_unlimited_coupon_even_if_used_many_times` で409（期待200）
- 原因の仮説：`usage_limit`がNULLのとき`or 0`で0に置き換わり、上限0枚と解釈される
- 判断：実装の欠陥（根拠：4-4「発行数の上限」：上限が設定されていない（null）クーポンは無制限）
- 修正内容：NULLチェックを明示（`is not None`）に変更

## 2：発行数の上限がnullのクーポンで、確定時に使われた回数を数えられない

- エラー内容：CPN-15 `test_checkout_with_unlimited_coupon_increments_used_count` で、1を直したあとも確定が409（期待201）
- 原因の仮説：UPDATE文のWHERE句で`used_count < NULL`がUNKNOWNになり、0件更新となる
- 判断：実装の欠陥（根拠：4-4「発行数の上限」：上限がなくても、使われた回数は数える）
- 修正内容：`usage_limit IS NULL OR`の分岐をSQLに追加

## 3：最低購入金額の「ちょうど」を弾いていた

- エラー内容：CPN-05 `test_apply_coupon_at_exact_min_purchase` で422（期待200）
- 原因の仮説：仕様は「以上」だが、実装が`<=`で弾いていて、ちょうどの金額を除外していた
- 判断：実装の欠陥（根拠：4-4：割引対象額が最低購入金額以上のとき使える）
- 修正内容：比較演算子を`<`に修正

## 4：セール品を割引対象額から除いていなかった

- エラー内容：CPN-16 `test_sale_items_are_excluded_from_eligible_subtotal` で割引対象額が6000（期待4000）。CPN-17 `test_apply_coupon_rejected_when_all_items_are_on_sale` も同じ原因で200（期待422）
- 原因の仮説：割引対象額の算出で、セール品を除外していなかった
- 判断：実装の欠陥（根拠：4-4：割引対象額は、小計からセール品と対象外カテゴリの商品を除いた金額）
- 修正内容：`is_sale`の商品を計算対象から除く処理を追加

## 5：定率の端数を四捨五入していた

- エラー内容：CPN-10 `test_percentage_discount_fraction_is_truncated` で501（期待500）
- 原因の仮説：設計は切り捨てだが、実装が`round()`（四捨五入）だった
- 判断：実装の欠陥（根拠：4-4：定率クーポンの割引額は、円未満を切り捨てる）
- 修正内容：整数除算（`//`）に変更
