# 基本設計書（EShop）

ECサイトEShopのバックエンドの基本設計書である。**機能を追加するときは、この設計書に追記する。**

## 変更履歴

| 版  | 内容                                                   |
| :-- | :----------------------------------------------------- |
| 1.0 | 初版（認証・商品一覧・カート・注文確定）               |
| 1.1 | クーポン機能を追加（No.2の設計をレビューして確定した版） |
| 1.2 | クーポンの発行数の数え方と、複数の条件に当てはまるときのエラーの扱いを追記 |

## 機能を追加するときの書き方

- 章は増やさない。追加する機能の内容を、それぞれの章に書き足す
- 新しい機能は「3. 機能一覧」に行を足し、実現するエンドポイントを書く
- 新しいエンドポイントは「9. 外部インタフェース（API）」に節を足し、一覧にも行を足す
- 既存のエンドポイントの動きを変えるときは、その節を書き換え、変わる点（追加する項目・エラー）を明記する
- 新しいテーブルや列は「8. データモデル」の表とER図の両方に足す
- 状況とステータスコードの対応は「10. エラー一覧」にも足す
- 決めた方針とその理由は、関係する章（業務ルール・スコープなど）に書く
- 変更履歴に1行足す
- 書くのは基本設計の範囲まで（規則・入出力・流れ）。SQLやクラスの作りは書かない

## 1. 概要・スコープ

### 1-1. 目的

一般の利用者が商品を選んでカートに入れ、注文を確定できるECサイトのバックエンドAPIを提供する。

### 1-2. 対象範囲

| 対象                     | 内容                                           |
| :----------------------- | :--------------------------------------------- |
| バックエンドAPI          | 本書の対象。`backend/`                         |
| 画面（`frontend/`）      | 対象外（本書では扱わない）                     |

### 1-3. スコープ外

| 項目                         | 理由・補足                                         |
| :--------------------------- | :------------------------------------------------- |
| 利用者の新規登録・退会       | 現行の版では利用者は初期データで用意する           |
| 商品の登録・変更（管理機能） | 現行の版では商品は初期データで用意する             |
| 決済・配送                   | 注文確定までを扱う。支払いと配送は扱わない         |
| 注文の参照・取り消し         | 現行の版には無い                                   |
| 複数クーポンの併用           | 1注文につき1枚まで。適用順で結果が変わる複雑さと、テストケースの増加を避けるため。複数のキャンペーンは、クーポンの種類を増やして対応する |
| クーポンの登録・配布（管理機能） | 現行の版ではクーポンは初期データで用意する。コードを知っていれば誰でも使える |
| 在庫管理                     | 在庫数は持たない。数量の上限も設けない             |

## 2. 用語

| 用語     | 意味                                                             |
| :------- | :--------------------------------------------------------------- |
| 利用者   | ログインしてカートと注文を使う人。本書の「ユーザー」と同じ       |
| カート   | 注文を確定する前に、利用者ごとに商品と数量を入れておく場所       |
| 小計     | 商品ごとの`単価 × 数量`の合計（円）                              |
| 注文確定 | カートの中身を注文として記録し、カートを空にすること             |
| クーポン | コードを入力すると割引されるもの。定率（%引き）と定額（円引き）がある |
| 割引対象額 | 小計のうち、セール品とクーポンの対象外カテゴリを除いた金額（`eligible_subtotal`） |
| 割引額   | クーポンで引く金額（円）                                         |
| 割引後の合計 | 小計から割引額を引いた金額（`total`）                        |

## 3. 機能一覧

| No. | 機能         | 概要                                               | エンドポイント           |
| --: | :----------- | :------------------------------------------------- | :----------------------- |
|  1  | ログイン     | メールアドレスとパスワードで認証し、トークンを発行 | `POST /auth/login`       |
|  2  | 商品一覧     | 登録されている商品を一覧で返す                     | `GET /products`          |
|  3  | カートに追加 | 商品と数量をカートに入れる                         | `POST /cart/items`       |
|  4  | カートの確認 | カートの中身・小計・割引額・割引後の合計を返す     | `GET /cart`              |
|  5  | 注文確定     | カートの中身で注文を確定する。適用中のクーポンがあれば再検証して消費する | `POST /orders` |
|  6  | 稼働確認     | サーバーが動いているかを返す                       | `GET /`                  |
|  7  | クーポン適用 | カートにクーポンを適用し、割引額をプレビューする（消費はしない） | `POST /cart/coupon` |
|  8  | クーポン取り消し | カートに適用中のクーポンを外す                 | `DELETE /cart/coupon`    |

## 4. 業務ルール

### 4-1. 金額

- 金額はすべて整数（円）で扱う
- カートの小計は、各商品の**現在の**単価で求める（`Σ 単価 × 数量`）
- 注文確定時も、その時点の単価で小計を求め直す。確定した注文には、そのときの商品名と単価を写し取って残す。あとで商品の価格が変わっても、確定した注文の金額は変わらない

### 4-2. カート

- 利用者ごとに1つ。同じ商品は1行にまとめ、追加するたびに数量を足す
- 数量は1以上。上限は設けない
- 注文を確定するとカートは空になる。適用していたクーポンも外れる
- カートに適用できるクーポンは1枚まで。適用中に別のクーポンを適用すると、エラーにせず**上書き**する

### 4-3. 注文の状態

注文は確定したときに作られ、状態は`confirmed`（確定済み）になる。現行の版では、ほかの状態へは移らない。

```mermaid
stateDiagram-v2
    [*] --> confirmed: 注文確定（POST /orders）
```

### 4-4. クーポン

**割引額の求め方**

- 割引対象額は、小計からセール品（`is_sale`が真）と、クーポンの対象外カテゴリの商品を除いた金額とする
- 定額クーポンの割引額は、クーポンの値と割引対象額の小さいほう
- 定率クーポンの割引額は、割引対象額×割合（%）。**円未満は切り捨てる**。割引上限額が設定されていれば、それを超えない
  - 切り捨ては事業者側に有利だが、割引額が上限を超えないことが保証され、返金などの処理と整合が取りやすい。四捨五入は金額によって切り上げと切り捨てが混ざり、説明が難しい
- 割引額は割引対象額を超えない。割引後の合計は0円未満にならない

**使える条件**

| 条件         | 内容                                                                                   |
| :----------- | :------------------------------------------------------------------------------------- |
| 有効期間     | 開始日時以上・終了日時**未満**（終了日時ちょうどは失効済み）。日時はUTCで持つ            |
| 最低購入金額 | **割引対象額**が最低購入金額**以上**のとき使える                                       |
| 発行数の上限 | 使われた回数が上限に達していれば使えない。上限が設定されていない（null）クーポンは無制限。上限が設定されていないクーポンでも、使われた回数（`used_count`）は数える |

- 「上限」は、**割引額の上限**（定率クーポンのみ）と**発行数の上限**の2つに分けて、両方を持つ。「使いすぎ」が1回あたりの割引額なのか、クーポン全体の利用回数なのか、要望からは決められないため
- 最低購入金額を割引対象額で判定するのは、セール品だけで最低購入金額を満たし、わずかな対象商品で割引を得る抜け道を作らないため
- 発行数の判定と加算は、同時に注文されても上限を超えないよう、1つの処理として行う

**プレビューと確定**

- `POST /cart/coupon`は割引額をプレビューするだけで、発行数は消費しない。消費は注文確定時に行う
- 注文確定時は、適用中のクーポンを、その時点の単価・カート・有効期間で**再検証**してから確定する。プレビューのあとに価格の変更・クーポンの失効・上限への到達が起こりうるため
- 適用中のクーポンが、カートの変更などで条件を満たさなくなったときは、`GET /cart`は割引額を0円として返す（適用中のコードは残す）。確定時の再検証でエラーになる

## 5. 権限（認可）

| 操作                         | 誰ができるか                                   |
| :--------------------------- | :--------------------------------------------- |
| ログイン・商品一覧・稼働確認 | 誰でも（ログイン不要）                         |
| カートに追加・カートの確認   | ログインした利用者。**自分のカートだけ**を扱う |
| 注文確定                     | ログインした利用者。**自分のカートだけ**を注文する |
| クーポンの適用・取り消し     | ログインした利用者。**自分のカートだけ**を扱う |

- どの利用者のカートかは、リクエストの値ではなく、トークンのユーザーで決める。ほかの利用者のIDを指定して操作する手段は無い

## 6. セキュリティ

- パスワードはbcryptでハッシュ化して保存し、平文では持たない
- ログインに失敗したときは、メールアドレスとパスワードのどちらが違ったかを返さない（登録済みのメールアドレスを推測させないため）
- トークン（JWT）の署名鍵などの秘密情報は、コードに書かず`.env`に置く

## 7. 処理の流れ

カートに商品を入れ、クーポンを適用して注文を確定するまでの流れ。

```mermaid
sequenceDiagram
    actor U as 利用者
    participant API as EShop API
    participant DB as データベース
    U->>API: POST /auth/login（メールアドレス・パスワード）
    API->>DB: 利用者を探し、パスワードを照合
    API-->>U: 200 アクセストークン
    U->>API: POST /cart/items（商品ID・数量）＋トークン
    API->>DB: 商品の有無を確認し、カートに追加（同じ商品なら数量を足す）
    API-->>U: 200 カートの中身と小計
    opt クーポンを使う場合
        U->>API: POST /cart/coupon（coupon_code）＋トークン
        API->>DB: クーポンを探し、有効期間・最低購入金額・発行数を確認
        alt 使えない
            API-->>U: 404 / 409 / 422
        else 使える
            API->>DB: カートに適用中のクーポンを記録（発行数は消費しない）
            API-->>U: 200 割引額と割引後の合計（プレビュー）
        end
    end
    U->>API: POST /orders（expected_total は任意）＋トークン
    API->>DB: カートを読み、現在の単価で小計を求める
    alt カートが空
        API-->>U: 400 カートが空です
    else クーポンを適用していない
        API->>DB: 注文と明細（商品名・単価を写し取る）を作り、カートを空にする
        API-->>U: 201 確定した注文
    else クーポンを適用している
        API->>DB: クーポンを再検証し、割引額を求め直す
        alt 使えなくなった・expected_total と合わない
            API-->>U: 409 / 422（何も変更しない）
        else 確定できる
            API->>DB: 発行数を1つ消費し、注文・明細・クーポンと割引額を記録して、カートを空にする（すべて1つの処理）
            API-->>U: 201 確定した注文
        end
    end
```

## 8. データモデル

```mermaid
erDiagram
    USER ||--o{ CART_ITEM : "カートに入れる"
    USER ||--o{ ORDER : "注文する"
    PRODUCT ||--o{ CART_ITEM : "入れられる"
    ORDER ||--|{ ORDER_ITEM : "明細を持つ"
    PRODUCT ||--o{ ORDER_ITEM : "注文される"
    USER ||--o| CART : "カートの状態を持つ"
    COUPON |o--o{ CART : "適用中"
    COUPON |o--o{ ORDER : "適用済み"
```

`CART`・`ORDER`とクーポンの関連は、IDではなくクーポンコードで持つ。注文の方は確定時の写しなので、あとでクーポンが変わっても注文は変わらない。

### User（ユーザー）

| 項目              | 型           | 説明                                                     |
| :---------------- | :----------- | :------------------------------------------------------- |
| `id`              | 整数         | 主キー                                                   |
| `email`           | 文字列・一意 | ログインID                                               |
| `hashed_password` | 文字列       | bcryptでハッシュ化したパスワード                         |
| `member_rank`     | 文字列       | 会員ランク（既定は`general`）。現行の機能では使っていない |

### Product（商品）

| 項目       | 型     | 説明                   |
| :--------- | :----- | :--------------------- |
| `id`       | 整数   | 主キー                 |
| `name`     | 文字列 | 商品名                 |
| `price`    | 整数   | 単価（円）             |
| `category` | 文字列 | 商品カテゴリ           |
| `is_sale`  | 真偽値 | セール品か（既定は偽） |

### CartItem（カートの明細）

利用者ごとに、商品1種類につき1行を持つ。

| 項目         | 型   | 説明                  |
| :----------- | :--- | :-------------------- |
| `id`         | 整数 | 主キー                |
| `user_id`    | 整数 | ユーザー（`User.id`） |
| `product_id` | 整数 | 商品（`Product.id`）  |
| `quantity`   | 整数 | 数量                  |

### Cart（カートの状態）

利用者ごとに1行。カートの明細（`CartItem`）は、これまでどおり`user_id`で利用者に紐づける。

| 項目                  | 型           | 説明                                   |
| :-------------------- | :----------- | :------------------------------------- |
| `id`                  | 整数         | 主キー                                 |
| `user_id`             | 整数・一意   | ユーザー（`User.id`）。1人1行          |
| `applied_coupon_code` | 文字列・null可 | 適用中のクーポンのコード。無ければnull |

### Coupon（クーポン）

| 項目                  | 型             | 説明                                                         |
| :-------------------- | :------------- | :----------------------------------------------------------- |
| `id`                  | 整数           | 主キー                                                       |
| `code`                | 文字列・一意   | クーポンコード                                               |
| `type`                | 文字列         | `percentage`（定率）または`fixed`（定額）                    |
| `value`               | 整数           | 定率なら割合（1〜100）、定額なら金額（円）                   |
| `max_discount_amount` | 整数・null可   | 割引上限額（円）。定率のみ使う。定額では常にnull             |
| `min_purchase_amount` | 整数           | 最低購入金額（円）。割引対象額で判定する（4-4）。既定は0     |
| `excluded_categories` | 文字列の配列・null可 | このクーポンで対象外にするカテゴリ                     |
| `usage_limit`         | 整数・null可   | 発行数の上限。nullなら無制限                                 |
| `used_count`          | 整数           | 使われた回数。既定は0                                        |
| `valid_from`          | 日時           | 有効期間の開始（UTC）                                        |
| `valid_to`            | 日時           | 有効期間の終了（UTC）。この日時ちょうどは失効済み            |

### Order（注文）

| 項目         | 型     | 説明                              |
| :----------- | :----- | :-------------------------------- |
| `id`         | 整数   | 主キー                            |
| `user_id`    | 整数   | 注文したユーザー（`User.id`）     |
| `subtotal`   | 整数   | 注文確定時の小計（円）            |
| `status`     | 文字列 | 注文の状態（4-3）。確定時は`confirmed` |
| `created_at` | 日時   | 注文を確定した日時（UTC）         |
| `coupon_code` | 文字列・null可 | 適用したクーポンのコード（確定時の写し）。無ければnull |
| `discount_amount` | 整数 | 割引額（確定時の写し）。クーポンなしは0 |

### OrderItem（注文の明細）

注文確定時点の商品名と単価を写し取って持つ（4-1）。

| 項目           | 型     | 説明                 |
| :------------- | :----- | :------------------- |
| `id`           | 整数   | 主キー               |
| `order_id`     | 整数   | 注文（`Order.id`）   |
| `product_id`   | 整数   | 商品（`Product.id`） |
| `product_name` | 文字列 | 確定時点の商品名     |
| `unit_price`   | 整数   | 確定時点の単価（円） |
| `quantity`     | 整数   | 数量                 |

## 9. 外部インタフェース（API）

### 9-1. 共通仕様

| 項目      | 内容                                                           |
| :-------- | :------------------------------------------------------------- |
| ベースURL | `http://127.0.0.1:8000`                                        |
| 形式      | リクエスト・レスポンスともJSON（UTF-8）                        |
| 日時      | UTCの日時をISO 8601形式の文字列で返す                          |
| API仕様書 | サーバー起動中は Swagger UI（`/docs`）で実際の定義を確認できる |

**認証**

- `POST /auth/login`でアクセストークン（JWT）を取得し、要認証のAPIではヘッダーに付ける
  ```text
  Authorization: Bearer <access_token>
  ```
- トークンの有効期限は60分（`.env`の`JWT_EXPIRE_MINUTES`で変わる）
- トークンには、ログインした利用者のメールアドレス（`sub`）と有効期限（`exp`）が入る

**エラーの返し方**

アプリが返すエラーは、`detail`に理由の文字列を入れて返す。

```json
{ "detail": "商品が見つかりません" }
```

リクエストの形式が合わない（必須項目が無い・型が違う・値の範囲外）ときは、フレームワークが**422**を返す。`detail`はエラーの配列になる（下の例は一部の項目を省略している）。

```json
{
  "detail": [
    { "type": "greater_than_equal", "loc": ["body", "quantity"], "msg": "Input should be greater than or equal to 1", "input": 0 }
  ]
}
```

状況ごとのステータスコードは「10. エラー一覧」にまとめる。

### 9-2. エンドポイント一覧

| メソッド | エンドポイント | 概要                       | 認証 |
| :------- | :------------- | :------------------------- | :--- |
| GET      | /              | 稼働確認                   | 不要 |
| POST     | /auth/login    | ログイン（JWT取得）        | 不要 |
| GET      | /products      | 商品一覧取得               | 不要 |
| POST     | /cart/items    | カートに商品追加           | 要   |
| GET      | /cart          | カート内容・小計取得       | 要   |
| POST     | /orders        | 注文確定                   | 要   |
| POST     | /cart/coupon   | クーポン適用（プレビュー） | 要   |
| DELETE   | /cart/coupon   | クーポン取り消し           | 要   |

### 9-3. GET /（稼働確認・認証不要）

レスポンス 200 OK

```json
{ "status": "ok" }
```

### 9-4. POST /auth/login（ログイン・認証不要）

リクエスト

```json
{ "email": "taro@example.com", "password": "your-password" }
```

| 項目       | 型     | 必須 | 説明           |
| :--------- | :----- | :--- | :------------- |
| `email`    | 文字列 | ○    | メールアドレス |
| `password` | 文字列 | ○    | パスワード     |

レスポンス 200 OK

```json
{ "access_token": "eyJhbGciOiJIUzI1NiIs...", "token_type": "bearer" }
```

### 9-5. GET /products（商品一覧取得・認証不要）

登録されているすべての商品を返す。並び順は指定しない。商品が無いときは空の配列を返す。

レスポンス 200 OK

```json
[
  { "id": 1, "name": "ワイヤレスマウス", "price": 2980, "category": "electronics", "is_sale": false },
  { "id": 3, "name": "モバイルバッテリー", "price": 3480, "category": "electronics", "is_sale": true }
]
```

### 9-6. POST /cart/items（カートに商品追加・要認証）

ログイン中の利用者のカートに商品を入れ、カートの内容を返す（4-2）。

リクエスト

```json
{ "product_id": 1, "quantity": 2 }
```

| 項目         | 型   | 必須 | 説明                   |
| :----------- | :--- | :--- | :--------------------- |
| `product_id` | 整数 | ○    | 商品のID               |
| `quantity`   | 整数 | －   | 数量。1以上。省略時は1 |

レスポンス 200 OK：`GET /cart`と同じ形で、追加後のカートを返す。

### 9-7. GET /cart（カート内容・小計取得・要認証）

ログイン中の利用者のカート・小計・割引額・割引後の合計を返す。クーポンを適用していないときは、`applied_coupon_code`はnull、`discount_amount`は0、`total`は`subtotal`と同じになる。カートが空のときは`{"items": [], "subtotal": 0, "applied_coupon_code": null, "discount_amount": 0, "total": 0}`を返す。

レスポンス 200 OK

```json
{
  "items": [
    { "product_id": 1, "product_name": "ワイヤレスマウス", "unit_price": 2980, "quantity": 2 }
  ],
  "subtotal": 5960,
  "applied_coupon_code": "SPRING10",
  "discount_amount": 596,
  "total": 5364
}
```

| 項目                 | 説明                                |
| :------------------- | :---------------------------------- |
| `items[].unit_price` | 商品の**現在の**単価                |
| `subtotal`           | `unit_price × quantity`の合計（円）。割引前の金額 |
| `applied_coupon_code` | 適用中のクーポンのコード。無ければnull |
| `discount_amount`    | 割引額（円）。適用中のクーポンが条件を満たさなくなったときも0（4-4） |
| `total`              | 割引後の合計（`subtotal - discount_amount`） |

### 9-8. POST /orders（注文確定・要認証）

ログイン中の利用者のカートの中身で注文を確定する（処理の流れは7）。クーポンを適用していれば、再検証してから確定する（4-4）。

リクエスト（ボディは省略できる）

```json
{ "expected_total": 5364 }
```

| 項目             | 型   | 必須 | 説明 |
| :--------------- | :--- | :--- | :--- |
| `expected_total` | 整数 | －   | 直前に`GET /cart`で見た`total`。クーポンを適用しているときだけ、求め直した金額と比べ、違えば422を返す。省略時は比べない |

レスポンス 201 Created

```json
{
  "id": 1,
  "status": "confirmed",
  "subtotal": 5960,
  "coupon_code": "SPRING10",
  "discount_amount": 596,
  "items": [
    { "product_id": 1, "product_name": "ワイヤレスマウス", "unit_price": 2980, "quantity": 2 }
  ],
  "created_at": "2026-10-01T01:23:45.678901"
}
```

### 9-9. POST /cart/coupon（クーポン適用・要認証）

ログイン中の利用者のカートにクーポンを適用し、割引額をプレビューする（4-4）。発行数は消費しない。すでに適用中のクーポンがあれば上書きする。

リクエスト

```json
{ "coupon_code": "SPRING10" }
```

| 項目          | 型     | 必須 | 説明           |
| :------------ | :----- | :--- | :------------- |
| `coupon_code` | 文字列 | ○    | クーポンコード |

レスポンス 200 OK

```json
{
  "coupon_code": "SPRING10",
  "eligible_subtotal": 5960,
  "discount_amount": 596,
  "subtotal": 5960,
  "total": 5364
}
```

| 項目                | 説明                         |
| :------------------ | :--------------------------- |
| `eligible_subtotal` | 割引対象額（4-4）            |
| `discount_amount`   | 割引額                       |
| `total`             | 割引後の合計                 |

### 9-10. DELETE /cart/coupon（クーポン取り消し・要認証）

適用中のクーポンを外す。適用中のクーポンが無くてもエラーにしない。

レスポンス 200 OK：`GET /cart`と同じ形で、取り消し後のカートを返す。

## 10. エラー一覧

| エンドポイント           | 状況                                               | ステータス | `detail`                                           |
| :----------------------- | :------------------------------------------------- | :--------- | :------------------------------------------------- |
| 要認証のすべて           | `Authorization`ヘッダーが無い                      | 401        | `Not authenticated`                                |
| 要認証のすべて           | トークンが不正・期限切れ・該当する利用者がいない   | 401        | `認証情報が無効です`                               |
| `POST /auth/login`       | メールアドレスが未登録、またはパスワードが違う     | 401        | `メールアドレスまたはパスワードが正しくありません` |
| `POST /cart/items`       | `product_id`の商品が無い                           | 404        | `商品が見つかりません`                             |
| `POST /orders`           | カートが空                                         | 400        | `カートが空です`                                   |
| `POST /cart/coupon`      | コードのクーポンが無い                             | 404        | `クーポンが見つかりません`                         |
| `POST /cart/coupon`・`POST /orders` | 有効期間の外                            | 422        | `クーポンの有効期限外です`                         |
| `POST /cart/coupon`・`POST /orders` | 割引対象額が最低購入金額に満たない      | 422        | `最低購入金額を満たしていません`                   |
| `POST /cart/coupon`・`POST /orders` | 発行数の上限に達している                | 409        | `クーポンの発行数上限に達しています`               |
| `POST /orders`           | クーポン適用中で、`expected_total`が求め直した金額と違う | 422  | `カート内容が変更されています。金額を確認してください` |
| すべて                   | リクエストの形式が合わない（必須項目が無い・`quantity`が0以下 など） | 422 | （形式エラー。9-1）                     |

1つの要求が、クーポンが使えない状況（有効期間の外・割引対象額が最低購入金額に満たない・発行数の上限に達している）の複数に当てはまるとき、どのエラーを返すかは定めない。

要認証のAPIで401を返すときは、`WWW-Authenticate: Bearer`ヘッダーも返す（ログイン失敗の401には付けない）。
